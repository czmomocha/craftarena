- 适用范围：Windows 与 macOS 开发机；窗口化运行主场景。Headless `--quit` **不是**真机。

- 命令以 [README.md](../../README.md) 为准，不要另猜参数。
- Agent 开下一章 PR 时必须**整节替换「本刀」**，不要把旧章步骤留在下面让人验错对象。无开发机可见行为的章：本刀只写「无」和一句原因。

## 共用启动（大厅窗口）

机关狂奔匹配大厅是代码创建的 `Window`，标题 **Traprush**。第一行是状态 Label。按钮（从左到右）：**Quick play**、**Create room**、**Join room**、**Solo play**、**Cancel**、**Poll**。其下一行是服务器地址：输入框（placeholder `Server host`，默认填当前控制面主机）加 **Apply server** 按钮。再往下三个输入框：房间码（placeholder `Room code`）、课程 id（默认 `course_01`）、人数（默认 `2`）。窗口里的 3D：玩家是**角色视觉资产**（一个约 1 米高的机器人），本席覆青色薄膜（`OWN_ALBEDO`），远端覆海军蓝薄膜（`REMOTE_ALBEDO`）。橙色盒是可破坏箱；洋红盒是周期机关（固体半周期才出现；官方赛道出生点 −Z 1 个）；**始终固体铺地块视觉**（黄黑警示条地砖，一格一块；官方赛道沿必经路铺立足面，`course_01` 另有出生点 −X 1 个，上层楼板在 −Z 三格）；视觉资产解析不出来时，角色与地块各自回退成原来的占位盒（青色 / 石色）。垫 / 门 / 终点仍是赛道占位盒（未开玩时垫是原绿、终点是原金；开玩后本席已验收垫是暗绿，当前目标垫是亮薄荷；全部垫完成后终点变亮金，冲线后变暗金）；条是传送连线与检查点顺序 gizmos。玩家盒上方有名次 Label；本席名次标以 `*` 开头。开玩时状态行含 `pads=n/m`、`floor=n`、`finish=n`、`crates=n/m`、`hazards=n/m` 与 `solids=n/m`。

### 0.2 打开窗口化主场景

**不要**用 Headless `--quit`。

| 平台 | 命令（仓库根） |
|---|---|
| Windows | `& $env:GODOT4 --path game` |
| macOS | `"$GODOT4" --path game` |

也可以先 `& $env:GODOT4 --editor --path game` / `"$GODOT4" --editor --path game`，再在编辑器里运行主场景。

预期：出现标题为 **Traprush** 的窗口；状态行含 `join=idle`、`play=idle`、`tls=off`、`server=127.0.0.1`、`course=3/5/1`（默认 `course_01` 的垫/门/终点占位；门含捷径上楼 `two_way`、安全路侧向 `two_way` 与上楼 `one_way`）。失败：没有窗口、立刻退出、或只有 Headless 日志。

操作：WASD 移动，空格跳跃（大厅按钮不抢空格），Q 或鼠标左键使用道具（打碎眼前箱；官方课出生点已拾爆破球），F 基础推击（推开邻座胶囊，无线上目标 id），Left Shift 或 **Sprint** 沿当前朝向冲刺一格（官方课出生点已拾冲刺），R 重置到最近已验收检查点。点过人数/课程/房间码/服务器框之后，再点 3D 区域或 Create room / Solo play，光标应离开输入框，WASD 才是移动。`course_01` 出生点 −Z 两格有洋红周期机关，有石色踏板可以走到它；踩上时若处于固体半周期会被击退并闪回出生点。

## 本刀：纠偏 C4 第 6 章 — D4 视口与镜头规格接线

对应：当前完整章节 PR。这一章把 [D4](../plans/course-correction-2026-08.md) 里最后两项「已拍板但尚未接线」接完，落点是 **E8 前半**（D4 数值进所有者文档）：

| 项 | 接线前 | 接线后 |
|---|---|---|
| 相机俯角 | 43.3°（`Vector3(6, 8, 6)` 的副产物） | **45°**（D4「斜 45°」）。水平方位角本来就是 45° |
| 相机距离 / FOV | 距离 √136、FOV 隐式取 Godot 默认 | **一位没改**，但显式写进 `PlaceholderSpec`。D4 没问这两项 |
| UI 基准 | 无。`viewport 1600×900`，2D 不缩放 | **1920×1080** + `canvas_items` / `expand`，落在**主窗口** stretch |
| 开发机运行窗 | `viewport` 兼当运行窗 | 搬到 `window_*_override`，1600×900 最大化不变 |

审查过程中人类在 4K 屏上发现两个问题，都已在本刀内修掉，**它们是本刀最需要你复验的部分**：

| 问题 | 是谁引入的 | 修法 |
|---|---|---|
| 鼠标 hover / 点击与按钮画的位置错开（点 Solo play 命中 Poll） | **本刀**（第一版给嵌入子窗口也设了 `content_scale`） | 撤掉子窗口那层，UI 基准只由主窗口 stretch 承担 |
| 帧率偏低、按键与空格反应迟钝 | **上一章**（C4 第 5 章给玩家接上 `.glb`） | `MatchSnapshotMap` 改为复用席位节点，不再每帧重新实例化角色 |

**这一章会改开发机可见表现**，所以它的验收就是"你看着对不对"，而不是"测试绿"。

**先做一次导入**：

```bash
"$GODOT4" --headless --path game --import     # Windows: & $env:GODOT4_CONSOLE --headless --path game --import
```

1. **鼠标点哪个就中哪个**（本刀回归，**大屏上必做**）：按 0.2 打开窗口，鼠标依次悬停 **Quick play → Create room → Join room → Solo play → Cancel → Poll → Sprint** 七个按钮。
   - 预期：悬停哪个，**哪个**变亮/出现悬停态；点下去执行的就是它。窗口右侧的 `Sprint` 按钮与第二行的 **Apply server** 都**在屏幕内看得见**。
   - 失败：悬停 Solo play 亮的是 Cancel 或 Poll（越往右偏得越多）；或者 `Sprint` / `Apply server` 看不见（被切出可视区）。两者是同一个 bug 的两面。
   - 背景：嵌入子窗口的 `content_scale` 在**渲染路径不生效、输入路径生效**，两者会错开 `1/factor` 倍。已有回归守卫钉住"子窗口不得设 content_scale"，但那只挡代码改错，挡不住引擎行为变化，所以这条要人眼看。
2. **帧率与手感**（上一章的回归，**本刀最值得你确认的一条**）：点 **Solo play**，按住 W 走一段，连按空格跳几次。
   - 预期：移动连续、跳跃即时响应；按住 W 时角色匀速前进，不是一顿一顿。
   - 失败：仍然黏滞、按键要按住一会才动。
   - 想看数字：Godot 编辑器里运行（`--editor` 后按 F5），**调试器 → 监视器**看 `Frame Time`。修复前每帧光是重建玩家节点就要 7.4 ms（Solo）/ 12.8 ms（2 人），而 60 FPS 全部预算只有 16.7 ms；修复后这一项是 0.015 ms。
3. **镜头是正等距的 45°**：仍在 Solo 里，看角色与地砖。
   - 预期：视线沿对角线俯视 45°。判据不是"感觉像"：找一格**正方形地砖**，它在屏幕上应是**上下对称的菱形**，左右对角线约为上下对角线的 √2 倍（≈ 1.41）。43.3° 时上下会略扁。
   - 失败：仍然偏扁（俯角没改）；或视线从正上方 / 正侧面来（角度算反了）。
4. **镜头远近和视野和上一章一样**：与上一章的截图比同一位置。
   - 预期：角色在画面里的**大小**、能看到的赛道范围**几乎不变**——只有角度转了。
   - 失败：突然拉远或推近 —— 那说明有人顺手改了距离或 FOV，而 D4 从没回答这两项。
5. **HUD 随屏幕等比缩放**：在 1080p 与更高分辨率屏上各看一次（或把窗口拖小到半屏）。
   - 预期：HUD 整体等比缩放，不是"字号不变、布局重排"。
   - 失败：字号在大屏上明显偏小。
   - 诚实边界：玩法 HUD 画在一个 1280×720 的嵌入子窗口里，随主窗口的 1920×1080 基准整体放大。所以它的**设计**基准仍是 1280×720，见下。
6. **Preview 壳是同一套镜头**：编辑器里打开 Preview 壳并开玩。
   - 预期：Preview 的俯视角与对局**一致**（两条壳读同一份 spec）；鼠标命中同样不偏。
   - 失败：两个窗口一个 45° 一个 43°；或 Preview 里鼠标偏了。
   - **Preview 里按住方向键仍会卡**，那是已知未修项，见「仍然欠着」。
7. **3D 没有被拉伸或降分辨率**：看角色边缘与地砖贴图。
   - 预期：清晰度与上一章相同。`canvas_items` 只缩放 2D，3D 仍按窗口真实分辨率渲染。
   - 失败：整个画面像被放大的低分辨率贴图（拉伸模式设成了 `viewport`）。
8. **本席与远端仍分得清**（复用路径的回归）：`npm run dev` 后 **Quick play**，人数 `2`，第二个客户端进同一场。
   - 预期：本席机器人覆**青**膜，远端覆**海军蓝**膜；两人走动时位置都跟得上，没有谁"卡在原地"。
   - 失败：两人同色（座位色没跟上复用路径）；或远端不动（位姿没更新）。
9. **赛道玩法一点没动**：WASD 走、空格跳、Q 打箱、Shift 冲刺、R 复位、踩洋红机关被击退。
   - 预期：与上一章逐项一致。镜头、UI 缩放与节点复用都不进权威仿真。

### 诚实边界

- **距离与 FOV 仍是占位**。D4 只回答了角度，所以这一章严格只改角度。屏幕上"远近合适"不构成对距离的拍板，见 [CD-11 §8.2](../../Confirmed-docs/10-product/11-scope-and-platforms.md)；
- **UI 基准只落在主窗口**。玩法 HUD 实际画在 1280×720 的嵌入子窗口里（`MODE_MAXIMIZED` 对嵌入子窗口不改 `size`，这是 M3 以来的既有行为），随主窗口的 1920×1080 基准整体放大。所以"HUD 按 1920×1080 设计"**尚未成立**，要么让子窗口铺满、要么不用子窗口，属 C5 拆壳范围；
- **鼠标偏移的自动化验证没做成**。我第一版探针用 `push_input` 测出"全部命中正确"，因为我的正向公式和引擎的输入逆变换是**同一个错误模型**、互相抵消 —— 自证成功。真正定位靠的是截图（渲染位置）与算术（`1824/1216.6 = 1.4993 = 1/0.6667`）。`Input.warp_mouse` 那条路在无人值守下不成立（要求窗口是 WM 焦点窗口）。所以**这条只有回归守卫 + 你的人眼**，没有自动门禁（宪法第二十四条）；
- **性能修复只断言身份，不断言耗时**。新测试钉的是"同一个节点实例被留下来了"（确定性），不是毫秒数（CI 上不稳，且 [CD-53 §1.1](../../Confirmed-docs/50-engineering/53-testing-and-ci.md) 不建自动性能门禁）。12.76 → 0.015 ms 是开发机一次性观察值，**不是**回归基线；
- **`project.godot` 由引擎序列化**（README「Godot 工程」）。本刀用一次性 `ProjectSettings` 脚本写入后删掉脚本。重新序列化后 `window/size/initial_position_type=1` 不再出现——它是 4.7.2 的默认值、引擎不写默认值，**不是行为变化**；
- **顺手还原了一处脏改动**：工作树的 `project.godot` 带着编辑器会话塞进的 `_mcp_game_helper` autoload，守卫测试本来就是红的。它不是本章产出。

### 仍然欠着（不因本章消失）

- **Preview 壳按住方向键仍全量重建**：`try_sample_play_move` → `try_apply_play_intent` → `_rebuild_map()` → `map.rebuild(整个世界)`，含每一块地砖 `.glb`。开发机实测同类重建 36 块 ≈ **63 ms**。改成增量要先有 diff 机制，是独立一刀；
- **挂课程 / 换课程会卡一下**：`MatchSolidMap.apply_bundle` 一次性实例化 36 个地砖 ≈ 63 ms。一次性、不在每帧路径，但可感知。真正的解法是共享网格或 MultiMesh；
- 远端协议层 RTT 回填、C3 网络参数锁定、E6 有美术后的可玩性签署、字体与本地化键、动画状态契约、D7 输入抽象层、角色胶囊尚未进资产表、垫 / 门 / 终点仍无独立视觉、扫掠取样代价无上限（宪法第十七条缺口）、`match_lobby_shell.gd` 已 1,516 行（E9 要求 < 400）。
