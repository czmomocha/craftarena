## 0. 准备

1. 仓库根 `npm run dev`（第 5、6、7 项要联机与结算写库）。
2. 按 [开发机窗口验收 0.2](dev-window-check.md) 开窗口化主场景。第 5 / 6 项要两个客户端。
3. 声音打开，先在 **设置** 里把五条总线拉到自己习惯的音量（第 5 项要判断"是否吵"，起点别是静音）。
4. 会用到的课：`course_01`（捷径 vs 安全路）、`course_04`（垂直塔）、`course_05`（双路线）、`course_f_playable`（机关展览，**不是**官方课）。
5. 一次签署建议 40–60 分钟连着做完；中断后从上一项重做，不要跨天拼结论。

## 1. 操作手感

1. `course_01` **单人试玩**。WASD 走、空格跳、Left Shift 冲刺、Q 打箱、R 复位。
2. 站在出生点连跳三次，再沿 +X 走五格冲线。
3. 联机（**创建房间**，人数 2，第二个客户端按码加入）里重复走跳，并对邻座按 F 推击。

判断：

- 按下到动起来，有没有让人想再按一次的迟滞？
- 跳跃弧能不能看出起落（不是同一帧抖一下）？
- 冲刺与推击有没有"做成了什么"的反馈？
- R 复位会不会误触、或想用时找不到？
- 联机里本席是否仍然跟手（本席走预测 overlay，远端走插值）？

诚实边界：跳跃高度、重力、推击力度、爆破半径、道具重生都是**占位值**（D-F4 / D-F5 / D-F6 未拍板）。这一项判断的是"当前这套值好不好按"，不是"数值定稿"。

---

## 2. 机关可读性

1. `course_04` **创建房间**或 Solo：看侧廊的电梯、弹射垫、压板。
2. `course_f_playable` Solo：沿 −Z 侧廊看喷火、滚柱、摆锤、地刺；主路上看能量墙、开关门、冰面、开关传送。
3. 每种至少让它伤到你一次。

判断：

- 不看文档，能不能看出哪一件会伤人、哪一件只是地形？
- 周期机关的开合半周期读不读得出来（预警够不够）？
- 喷火（能穿过去但会烫）和滚柱（半周期挡路）能不能一眼区分？
- 冰面、传送带这类"会带着你走"的，踩上去之前有没有提示？

诚实边界：全部占位程序化网格，不是定稿美术。判断的是**可读性**，不是好看。

---

## 3. 路线选择

1. `course_01` Solo：先走 +X 五步捷径冲线；再走一遍从检查点 1 向 +Z 的安全长路。
2. `course_05` Solo：先走安全长路；再站能量墙 −Z 侧按 Q 打碎，走短路。
3. `course_f_playable` Solo：危险捷径（打碎能量墙沿 +X）与安全路（+Z 绕检查点 1）各一遍。

判断：

- 两条路都值得选一次吗，还是有一条明显是废选项？
- 捷径的"风险换时间"感受得到吗？
- 走错路时，能不能看出自己走的是长的那条（`next=` 导航行、头顶箭头够不够）？

---

## 4. 失败反馈

1. `course_01` Solo：踩出生点 −Z 两格的滚柱（固体半周期）⇒ `hazard`。
2. 沿任意方向走出 ±8 格开发桩 ⇒ `out_of_range`。
3. `course_f_playable` Solo：站进压板正下或让开关门关在身上 ⇒ `crushed`。
4. 联机里重复第 1 步。

判断：

- 被打回时，知不知道"为什么"？
- 知不知道"回到哪里"，以及进度有没有退？
- 1.0 秒硬直是嫌长还是没感觉？
- 本局失败次数 HUD 有用还是噪音？
- **联机里读不到失败原因**（v1 快照帧没有该字段，加字段属宪法第十八条）——这个缺口在纵向切片阶段能不能接受？

---

## 5. 音频反馈

1. `course_f_playable` Solo：跑动（脚步节流）、跳、落地、打箱、过垫、传送、冲线、三种环境失败各听一次；走近传送带 / 电梯 / 喷火 / 滚柱 / 压板 / 摆锤 / 传送门听循环环境音。
2. 大厅 → Solo → 冲线 → 取消，听四态 BGM 切换（`lobby` / `play` / `result` 回 `lobby`）。
3. 两个客户端进同一房：听远端玩家动作是否有 3D 定位。
4. 打开 **设置**，把音乐拉低、音效留着，判断分轨是否有意义。

判断：

- 关键事件（打碎、过垫、冲线、失败）是不是都有声，且能区分？
- 按住方向键连续跑动会不会爆音？
- BGM 切换突不突然？循环接缝能不能忍？
- 走近机关的环境音是帮助判断，还是变成噪音？

诚实边界（[M5 计划 §3.5](../plans/m5-traprush-vertical-slice.md)）：v1 快照没有 `vy` / `stun` / 事件字段，**联机的跳跃、落地、硬直音是相邻快照位姿近似**，会漏播也会误播；机关环境音由客户端按快照 tick 重算，与服务端开合可能差一两拍；Web 导出的延迟与桌面不同，只验"能听见"。

---

## 6. 结算清晰度

1. 两个客户端进同一房（人数 2），两人都冲线。
2. 看状态行 `result=` 与 `settled=`，以及结算表（名次行 + MVP）。
3. 再跑一局，让一人先冲线、另一人晚几秒，确认名次顺序。

判断：

- 谁第一、自己第几，能不能一眼看懂？
- MVP 是"看得出为什么"还是凭空出现？
- 未冲线的人被排在哪，是否解释得通？
- 冲线到出结算之间的等待，会不会让人以为卡住了？

诚实边界：一期只有**单局名次与 MVP**，没有 MMR / 段位 / 赛季（宪法第十五条）。这一项不判断"排名系统够不够"。

---

## 7. 创作流畅度

1. 大厅点 **创作课程**，从空白做一张能冲线的课：检查点 → 立足固体 → 终点，再加一件机关与一件可破坏。
2. 边摆边在右侧 Preview 试玩；用点选拖拽改位置，用 Undo 撤一步。
3. 验证面板绿了之后点 **发布**，记下 `publish=ugc_…@1`。
4. 返回大厅 → **内容广场** → 找到自己那行 → **单人试玩** 一次。
5. 再从广场那一行 **创建房间**，复制邀请串，第二个客户端按码加入，两人跑完一局。

判断：

- 第一次做一张能跑的课，实际花了多久？卡在哪一步？
- "改一下就能在 Preview 里看到"够快吗（[CD-53 §3](../../Confirmed-docs/50-engineering/53-testing-and-ci.md) 的 Edit→预览 目标是 ≤ 30 秒）？
- 验证器告诉你的"为什么不能发布"看得懂吗？
- 发布 → 广场 → 邀请 → 联机这一串，中间有没有你会放弃的一步？

## 8. 外人 5 分钟上手（负责人自评）

1. 把第 7 项做出来的课留在广场里。
2. 自己从"刚打开客户端"的状态开始计时：默认课 Solo 冲线一次 + 联机建房一次。
3. 设想一个没看过任何文档的朋友照同样顺序做。

判断：

- 他能在 5 分钟内自己开一局并冲线一次吗？
- 哪一步最可能把他卡住（服务器地址框？课程 id 框？人数？房间码？）
- 需要你在旁边说的每一句话，都是一条 UI 缺口——记下来。

**诚实边界（重要）**：[CD-53 §1.1](../../Confirmed-docs/50-engineering/53-testing-and-ci.md#11-不对称强度策略) 明确"纵向切片期间不组织外部真人试玩"。因此本项是**负责人的判断**，签"通过"**不得**被表述为"已验证外人可上手"或"已做过外部测试"（宪法第二十四条）。真人测试要另立项。
