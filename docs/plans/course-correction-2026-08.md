## 0. 结论与本方案要解决的偏差

审视结论：**工程纪律罕见优秀，但已经跑偏了赛道。**

底座（定点仿真、服务器权威、回放哈希、契约与红线门禁）质量真实且可验证。偏差在另一侧：

| 偏差 | 可验证事实 |
|---|---|
| 核心玩法未成形 | 无重力/下落；零道具；官方赛道 5 步走完 |
| 从未离开开发机 | 无 `export_presets.cfg`；`infra/compose` 与 `infra/tencent-cloud` 仅 `.gitkeep` |
| 网络参数在错误条件下决策 | 插值 / 预测 / 快照节奏全部在 `127.0.0.1` 零延迟下调出 |
| 零美术、零规格 | `game/` 内 0 个 `.glb` / 0 个 `.gdshader`；`src/` 下 7 个 `.tscn` 全为 2–6 行空壳 |
| 占位常量正在固化 | 占位几何/数值已被 940 个 GUT 测试、3 张官方赛道 JSON、三条壳共同引用 |
| 表现层先于玩法 | 已交付 15+ 章占位表现映射（分色 / 朝向 / 高亮 / 名次 / 摄像机 / HUD） |
| 审查带宽已击穿 | 7 天 102 个合并 PR ≈ 每天 15 次人类 review + 15 次真机走查 |
| 部分门禁与风险状态虚标 | `game/tests/` 的 `integration/` `replay/` `content/` `security/` 四目录全空；CD-53 §4.2–§4.4 无实现状态标注 |
| 好不好玩零信息 | 无外部测试（已接受）+ 无 BotRunner + 无可玩内容 ⇒ 三重缺口叠加 |

**两个必须改变的判断**，本方案围绕它们组织：

1. **导出与真网络不是"验证步骤"，是"参数决策的前置条件"。**
2. **"不是产品数值"的声明不能替代"不要固化"的纪律。**

## 1. 冻结令

人类已声明：纠偏完成前不进行原计划中新的功能开发。本节把它写成可执行边界。

### 1.1 冻结（不得开工）

- CD-61 M3 剩余的**表现层增强**类章：镜头、UI、颜色、标签、HUD 字段、gizmos、皮肤、动效；
- M4 全部（Rule VM、gas、签名、发布管线、热生效、回滚）；
- M6 / M7 全部（BASTION）；
- 第 4 张及以后的官方赛道；
- 任何**新增**对 §5.1 冻结常量的引用点。

### 1.2 不冻结（本方案的工作本身）

C0–C5 六个批次。其中 C3 会写玩法代码，**它不是"新功能"，是补回被跳过的核心前提**——没有重力与道具，M3 的验收条"客户端不能伪造道具"在结构上无法满足，M5 的"可玩性签署"也无对象。

### 1.3 例外通道

阻断性缺陷（CI 红、`main` 不可运行、数据损坏）可修，按最小变更，并在 PR 标注 `[freeze-exception]` 与理由。

## 2. 纠偏目标与非目标

### 目标（全部可验证）

| # | 目标 | 判定方式 |
|---|---|---|
| G1 | 项目能离开开发机 | 存在 Windows 安装包，且包内行为经清单核查 |
| G2 | 网络参数在真实条件下决策 | 远端测试机 + 两台真机跑通一局，并留下 RTT/丢包基线数据（机房/规格/域名不锁进仓库） |
| G3 | 存在"是否好玩"的反馈回路 | BotRunner 能自动判定官方赛道可完成性；人类能在有重力、有道具的赛道上给出结论 |
| G4 | 占位不再固化 | `GameplayAsset` 契约落地：权威碰撞与视觉网格分离且各自版本化 |
| G5 | 审查带宽回到可持续区间 | 章粒度提高后，人类 review 频率降到可深审的水平 |
| G6 | 文档与门禁不再虚标 | CD-53 §4.2–§4.4 与 CD-62 的状态与事实一致 |

### 非目标（避免纠偏自身膨胀）

- 不做完整美术生产，只做**契约 + 规格 + 第一批替换**；
- 不做正式 Production、备份、监控、告警（仍属 [CD-63 §4](../../Confirmed-docs/60-plan/63-open-decisions.md) 阻断清单）；
- 不引入 Rule VM；
- 不引入 BASTION；
- 不做移动端触控完整方案（只做输入抽象层，见 D7）；
- 不建立自动性能回归门禁（[CD-53 §1.1](../../Confirmed-docs/50-engineering/53-testing-and-ci.md) 仍成立）。

### C1 — 真机与真网络基线

**为什么现在**：它是 C3 网络参数决策的前置条件。每晚一天，就多一章基于零延迟条件的代码。

**产出**

1. `game/export_presets.cfg`：Windows / Linux Headless 两个预设（其余按 D2 决定）；
2. 第一个 Windows 包，并按**包内核查清单**逐条验证：
   - `res://content/official/traprush/*.json` 在包内可读（导出过滤是否含 `.json`）；
   - `user://authoring_draft.json` 落点正确、草稿恢复可用；
   - 包内**不含** `_mcp_game_helper` autoload（[CD-62](../../Confirmed-docs/60-plan/62-risk-register.md) 该条风险的"已缓解"至今未经实证）；
   - Compatibility 下运行时创建的 `StandardMaterial3D` 表现与编辑器一致；
   - `OS.has_feature("web")` 分支行为符合预期；
3. `infra/tencent-cloud/` 与 `infra/compose/` 落地为可执行部署产物（模板 + 环境变量占位，**不写死**主机地址）；人类在自备测试机上拉起控制面 + 网关 + MatchHost；
4. **测试期传输**：远端联机走明文 `http`（控制面）与 `ws`（网关）。域名、Let's Encrypt、`wss://` **不是本批必须项**（2026-08-27 修订；公开运营前仍须 TLS，见宪法第二十二条与 D11）；
5. **双机真网络对局**：两台真机（不同物理机，至少一台走真实公网）经人类自备的远端测试机完成 `course_01` 一局并写库；
6. 网络基线：24 小时 RTT / 丢包 / 抖动采样，入 `docs/runbooks/`；
7. per-process CPU / 内存基线（7 局并发是 CPU 先崩，不是内存；容量核算见 D3，不把某台机器的规格写成产品常量）。

**验收**

- 一份 `docs/runbooks/desktop-export-check.md`（包内核查清单，可复跑）；
- 一份 `docs/runbooks/server-deploy.md`（通用部署步骤，供人类在自备机器上操作；用占位符，**不写死** IP、域名、VPS 规格、发行版、SSH 落点）；
- 一份基线数据文件，含 RTT P50/P90/P95、丢包率、并发进程资源占用；
- 双机对局有截图或日志证据，且结算记录在测试机上的库里；
- **明确写出哪些现有网络参数在真条件下失效**（这是本批最重要的产出，不是"跑通了"）。

**不做**：不做移动端导出；不做自动扩缩容；不做监控告警；不申请域名；不配 Let's Encrypt / 生产 CA；不把真实主机地址、SSH 私钥或证书写入仓库。

**预估**：3–5 章。

4. CD-53 §4.2 / §4.3 / §4.4 补"当前实现状态"标注（§4.1 已有，做得对，其余三节缺）。

### C3 — 核心玩法前提补齐

**为什么现在**：竞速游戏没有重力就没有手感与关卡设计空间；没有道具就无法验证 M3 验收条与 CD-21 五大支柱之一。

**产出**

1. **权威重力 / 下落**：定点积分，进入状态哈希与磁带回放，覆盖跳跃弧线与落地；随后把 `±8 格出界复位开发桩`从"兜底手段"降为"真正的边界保护"；
2. **道具最小集**（**具体道具由 D5 拍板**，[CD-63 §1.1–§1.3](../../Confirmed-docs/60-plan/63-open-decisions.md) 未锁，AI 不得自选）：服务端裁决的拾取、使用、冷却、命中；
3. **机关伤害 / 击退最小实现**（按 D5 一并拍板）：当前周期机关只切换固体，不读 `damage` / `knockback`；
4. **在 C1 真网络条件下重新锁定**：Tick 频率、输入发送频率、快照频率、插值窗口、对账阈值（[CD-63 §1.5](../../Confirmed-docs/60-plan/63-open-decisions.md)，原文即要求"实测决定"）；
5. **一张真正符合 CD-61 §4.1 语义的赛道**：不只逐条打勾，而是有落差、有 90 秒量级、有"安全路线 vs 危险捷径"的真实取舍。

**验收**

- 重力有 GUT + 回放哈希覆盖；跳起来会落下，落点确定性可复现；
- 道具有服务端裁决测试（伪造命中被拒）；
- 网络参数有实测依据并写入所有者文档，**不再是占位桩**；
- BotRunner（C2）能在新赛道上判定可完成；
- 人类在真机上能给出第一次"是否好玩"的结论——这是 G3 的落点。

**不做**：不做完整道具表；无控保护仍属 CD-63；复活硬直秒数已由 D5 选 1.0 s 并对局接线；不做远端外推的高级平滑。

**预估**：5–7 章。**这是六个批次里最重的一批。**

### C4 — 资产契约与美术规格

**为什么现在**：`GameplayAssetVersion` 是架构决策而非美术任务。[CD-31 §5](../../Confirmed-docs/30-ugc/31-ugc-principles.md) 承诺"碰撞、占地、导航、挂点属不可变 `GameplayAssetVersion`"，而今天全部占用都是"1 米盒、半长 `cell/2`"——**权威碰撞与视觉网格尚未分离**。分离会反向修改 SimulationBundle 六个袋的 Schema，属 P4 等级（[CD-33](../../Confirmed-docs/30-ugc/33-hot-publish.md)），**必须在 M4 冻结 Schema 之前完成**。

**产出**

1. 人类填完 §4 的**美术规格数值表**（D4）；
2. `GameplayAsset` 契约：视觉网格 / 权威碰撞形状 / 占地 / 挂点四者分离，各自版本化；视觉走 `latest`，玩法四项不可变；
3. 资源目录约定 + 导入规范（[CD-51 §5](../../Confirmed-docs/50-engineering/51-dev-environment.md) 目前只有一句"统一 GLB"）+ 性能预算表（Draw call / 材质数 / 纹理尺寸 / 骨骼上限）；
4. 动画状态契约（跑 / 跳 / 落地 / 推击 / 受击 / 破坏 / 传送）——先定契约，不做动画；
5. **第一批占位替换**：1 个角色 + 1 组地形块，走完 DCC → GLB → LFS → 导入检查 → 权威碰撞分离的完整链路；
6. 本地化键补齐（[CD-11 §8](../../Confirmed-docs/10-product/11-scope-and-platforms.md) 承诺"第一天使用本地化键"，实际 HUD 是硬编码中文）。

**验收**

- 第一个 `.glb` 入库并通过导入检查，LFS 正常；
- 权威碰撞不再等于视觉网格，且有测试断言二者可独立变更；
- 改一次视觉不产生新内容版本；改一次碰撞必须产生新 `GameplayAssetVersion`；
- 角色比例、相机、色板不再是 AI 自选的占位常量。

**不做**：不做全套美术；不做音频实装（只定清单与总线契约）；不做 shader 特效（描边是否引入见 D8）。

**预估**：4–6 章。

配套：新增章若必须读这些值，改为**从单一配置源注入**，不再散落 `const`。这样 D4 拍板后只改一处。

### 5.2 章粒度与审查抽样

**粒度下限**：一章必须是一条完整产品或技术链路的闭合。以下不再单独成章（应合并）：颜色调整、单个 HUD 字段、按钮焦点、窗口尺寸、Label 前缀。

反例（M3 后段实际发生）：「本席分色」= 盒子涂青 + 名次加 `*`；「开发机运行窗口与空格跳跃」= 按钮设 `FOCUS_NONE` + 窗口 1600×900。这两章各自走了「改 4 份文档 + 写 GUT + 整节替换真机清单 + 人类真机走查 + PR + CI + 人类合并」的完整流程，**流程开销数量级超过变更价值**。

**审查分级**（解决"每章等权 ⇒ 每章都浅"）：

| 级别 | 范围 | 要求 |
|---|---|---|
| 深审 | `shared/` 契约、协议帧、权威裁决、Schema、`backend/contracts/`、安全边界 | 逐行 + 真机 + AI 口头解释失败模式 |
