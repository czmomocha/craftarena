## 1. 参考玩法拆解

来源：`docs/萌宠跑酷玩法介绍.html`、[Steam 页](https://store.steampowered.com/app/2572560/Messy_Up/)。

| 参考的乐趣点 | 具体表现 | 我们已有的对应 | 缺口 |
|---|---|---|---|
| 一局约 1 分钟，节奏紧凑 | 起跑 → 连续机关 → 冲线 | 倒计时 R1、检查点、终点 | 现有课要么很短（01–05 在 ±8 盒内）、要么是迷宫（06/07 叠层 / 折返），**没有一条线性 1 分钟赛道** |
| 线性推进、永远知道往哪跑 | 高空工地，路线一眼看懂 | 导向箭头、检查点序号 | 出界盒 ±8 格含 Y，逼着课往回折 |
| 跑 / 躲 / 冲 / 比 四个动词 | 方向 + 一个冲刺技能 | 移动、跳、冲刺（拾取）、推挤、炸弹 | 冲刺是拾取消耗品，不是冷却技能——可用"每段入口一枚"模拟"本段有技能" |
| 机关有节奏可读 | 摆锤、传送带、压机、火焰 | 摆锤 / 传送带 / 压机 / 喷火 / 滚筒 / 地刺 / 移动平台 / 弹射垫全都有 | 全局同 cooldown 锁步——可以设计成"绿波" |
| 失误代价轻、马上再来 | 掉下去从最近点重来 | 检查点复位 + 60 tick 硬直 | 走出边缘没有起跳宽限：平地 1 格坑的起跳窗口约 5 tick（83 ms），**太苛刻** |
| 1v1 实时对比 | 分屏、进度百分比、1st/2nd | 名次 HUD、Solo 幽灵 | **没有双方进度条** |
| 路线选择 | 安全慢路 vs 冒险快路 | 能量墙 + 炸弹、多条路 | 现有官方课没有刻意的"二选一" |
| 身体对抗 | 窄桥上挤 | 推挤 1/4 格 | 需要在课里刻意安排一格宽咽喉 |

**标杆课的判据**：线性、1 分钟上下、每段一种主机关且节奏可读、至少两处路线二选一、至少五处一格宽咽喉可推挤、失误回退不超过一段。

## 3. 课的设计：「萌宠工地冲刺」`course_08`

### 3.1 全局约束（设计推导出来的，不是口味）

- **只往 −X 与 −Z 推进**。镜头在 +X+Z 上方 45°，W = 世界 −Z；屏幕上 −Z 是右上、−X 是左上。往 +X/+Z 走等于跑向镜头，看不见前方。
- **护栏只放远离镜头的一侧**（−X 腿放在 −Z 侧，−Z 腿放在 −X 侧）。1 格高方块在镜头侧会整个挡住 0.375 格高的角色。
- **检查点只放一格宽咽喉**，两侧是虚空或远侧墙。检查点是 1 格垫，宽路上会被绕过；咽喉同时是 1v1 推挤点。
- **不同高度的段 xz 不重叠**。弹射垫峰值约 4.25 格，上方有地板会被顶住（A3 的教训）。
- **起跑腿沿 −X**，席位偏移沿 −Z（`SPAWN_STRIDE`）变成横向并排，公平；起跑平台 z 方向留够 8 席。
- 坐标全部在编辑器平移范围（±64）内，本设计 x ∈ [−41, 44]、z ∈ [−40, 38]、y ∈ [−1, 8]。
- 下文"地板 y"= 站立层 s − 1；"放在 s"= 站立层高度上的实体（机关、拾取、检查点）。


### 3.4 预算与时长

- 实体约 650–700（course_07 档位）。没有实体数 CI 门禁，照实记数即可。
- 纯步行路径约 150 格 ≈ 40 s；加机关等待、弹射滞空、台阶起跳，**世界纪录目标 45–60 s**，普通玩家含失误 60–90 s。实测以 P2 跑手为准，偏短就加长 S2 / S6（多一个摆锤 / 多一排火），偏长就砍 S8 行数。
- 出界范围（按 P1a 规则）：x [−45, 48]、y [−8, 12]、z [−44, 42]。

### 3.5 验收（AI 侧可自动化的部分）

1. 构建脚本走真实 `place` 路径，写出 JSON，末行 `RESULT: PASS`；
2. 编译通过、`--package-check` 通过；
3. 完赛探针（快速提示路线）完赛；
4. **真人节奏跑手**按手写按键磁带完赛，打印总 tick 与每个检查点分段 tick；世界纪录落在 45–60 s；
5. 每个检查点可达、终点只能按序完成（绕过任一检查点冲线被拒）；
6. `course_01`–`course_07`、`course_f_playable` 的出界范围与原 ±8 立方体逐字节一致；
7. 白名单：Godot `MATCH_IDS`、backend enum、BotRunner / 内容验证器列表、测试同步。

人类侧：[开发机窗口验收](../runbooks/dev-window-check.md)本刀的编号步骤；可玩性结论留给 F2 重签，AI 不代签。
