## 1. 热修改等级

| 等级 | 内容 | Preview | 已开始的公开对局 |
|---|---|---|---|
| P0 表现 | 材质、音效、非权威特效 | 即时生效 | 全量下发，在安全边界生效 |
| P1 参数 | 伤害、速度、计时、耐久 | 安全边界生效 | 仅兼容白名单参数；全量下发并提示 |
| P2 拓扑 | 增删实体、移动路径、修改传送 | 安全 Tick 原子生效 | 禁止 |
| P3 规则 | 规则图和胜负逻辑 | 重编译后生效 | 禁止 |
| P4 Schema | 新组件、新命令、新节点类型 | 重启预览运行时 | 发新客户端/服务端版本 |

公开对局开局锁定不可变基础 `ContentHash`。P0/P1 **不覆盖**基础版本，而是形成不可变 `PatchHash` 序列；对局、结算和回放都记录基础哈希与按序应用的补丁。

## 2. 发布流水线

```text
草稿
→ 本地验证
→ Preview Session
→ 提交长期测试环境
→ 完整 Schema / 语义 / 预算验证
→ 最多 60 秒同步快检
→ 安全与资源扫描
→ 编译 SimulationBundle
→ 生成 ContentHash
→ 平台签名
→ 原子切换 latest 指针
→ 自动进入测试环境公共列表
→ 最长 10 分钟后台抽样仿真更新验证状态
```

### 2.1 发布目标

- 同步技术快检目标 ≤ 60 秒；
- 基础版本激活后新房使用新版本；
- P0/P1 在运行中房间的下一玩法安全边界生效；
- 发布失败不得留下半更新状态；
- 客户端缺少资源时先下载验证，再进入房间。

## 3. 热生效边界

- 已开始的公开对局锁定 `ContentId + Version + ContentHash`，另记录 P0/P1 `PatchHash` 序列；
- P2/P3 发布**绝不**改变运行中的公开对局，新建对局使用新版基础内容；
- P0/P1 验证通过后立即全量下发给所有对应运行中房间，不做灰度；
- P1 只在检查点/赛段切换、波次间等玩法安全边界生效，并显示版本提示；
- 技术异常由每场进程内硬阈值或 MatchHost 子进程退出检测触发自动回滚：补丁后崩溃、Tick 超预算、规则错误、非法状态或该房间连接异常；
- 平衡性问题只允许创作者或管理员手动回滚；
- 严重安全问题可以停止创建新房并终止问题对局；
- 基础内容回滚切换 `latest` 到已签名旧版本；运行中补丁回滚追加反向 Patch，不覆盖历史；
- 版本不可覆盖，只能递增；
- 回放和单局结算始终记录基础内容哈希及完整补丁顺序。

### 3.1 自动回滚的能力边界

一期没有运维监控和主动告警。P1 自动回滚只能依赖 MatchServer / MatchHost 的**本地硬阈值**，无法感知跨房间的全局崩溃率或断线率突增，也不能依赖外部仪表盘或告警系统。

该限制属于已接受风险，见 [CD-62 风险登记册](../60-plan/62-risk-register.md)。

## 4. 代码热更新禁区

内容热更新**不等于**代码热更新：

- 规则图、参数、地图和平台可信资源可以走内容管线；
- 新 GDScript、GDExtension、原生 SDK 和 Schema 变更必须发新程序版本；
- 不以 PCK 为借口绕过应用商店规则；
- 微信小游戏更新遵守微信包体和审核要求；
- AI 不得把"修改代码"伪装成"修改内容"。
