## 1. 玩法与数值细节

1. TRAPRUSH 道具栏槽位数、替换、放弃和叠加规则；
2. 两玩法的正式道具、炮塔、单位、障碍数量与最终清单；
3. 伤害、冷却、复活硬直、推击力度、无控保护、刷新时间等具体数值；
4. 各阶段默认时长、官方地图目标局时与 UI 动画时长；
5. Tick、输入发送、快照频率、插值窗口和对账阈值；
6. BASTION 隐藏布障的协议实现，包括服务器裁剪、提交揭示或其他方式；
7. 具体性能预算和香港真实网络门禁。

## 2. 工具与平台细节

2. PostgreSQL 迁移触发条件与托管方式；
3. GodotSteam 的具体能力清单；
4. 正式 Production、备份、监控、告警、抗滥用与可访问性何时立项。

## 3. 明确跳过的运营类议题

Bug 提交、客服、通知、告警展示及同类运营交互暂不决策，待进入后续开发或公开测试准备阶段再讨论。

## 4. 正式公开运营前必须重审（阻断清单）

以下不是可无限延期的实现细节，而是从长期测试环境进入正式公开运营前的**阻断清单**：

1. UGC 权利条款、平台运行/缓存/展示授权和测试者同意；
2. 注册与登录防滥用、公开用户名文本治理；
3. 内容刷屏治理、下架权限和主动作弊处置；
4. 数据备份、恢复演练、服务探测和主动告警；
5. 外部真人玩法与创作者易用性测试；
6. AI 资产来源、投诉和下架流程。
