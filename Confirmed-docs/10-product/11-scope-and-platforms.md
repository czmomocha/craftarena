## 1. 项目名称与愿景

正式名称：**Craft Arena**（英文）／**工坊竞技场**（简体中文）。

按 [CD-52 §6](../50-engineering/52-ai-workflow.md) 的语言约定，中文名只用于简体中文 UI 与对外中文材料，代码、协议字段与仓库标识一律使用英文名的下列形式：

| 用途 | 写法 |
|---|---|
| GitHub 仓库名 | `craftarena` |
| 文件、目录与本地化键 | `craft_arena` |
| GDScript 类名、TypeScript 类型 | `CraftArena` |
| Godot 项目 `config/name` | `Craft Arena` |

玩法代号 `TRAPRUSH` 与 `BASTION` 不受本节影响，仍按第 2 节表格使用。

打造一个适合 AI 主导开发、支持快速创作和快速验证的轻 3D UGC 游戏底座。玩家既可以游玩官方和社区内容，也可以通过低门槛 Edit 模式修改地图、机关、障碍、路径、炮塔槽位和有限规则，并在很短时间内进入单人或多人测试。

项目不追求首版就成为通用游戏创作平台。第一版只验证四件事：

1. 两个差异明显的玩法能否复用同一套仿真、内容和发布底座；
2. 创作者能否在不写代码的情况下做出可玩的玩法变体；
3. 从修改内容到进入多人测试是否足够快；
4. AI 能否在严格规则和自动化测试约束下承担大部分实现工作。

## 2. 产品构成

采用"同一品牌、账号和大厅，一套 UGC 创作与联机底座，两个按需资源玩法频道"的结构。

两个玩法的可信 GDScript **随基础客户端发布**；按需模块只能下发平台资源、官方内容和 UGC 数据，禁止远程下发玩法代码。

| 玩法 | 代号 | 一句话定位 | 详规 |
|---|---|---|---|
| 机关狂奔 | TRAPRUSH | 轻动作竞速：道具穿越、规避或击毁障碍，通过上下层与左右区块互联的传送网络完成多路线竞速 | [CD-21](../20-gameplay/21-traprush.md) |
| 双塔要塞 | BASTION | 低动作塔防对战：赛前为对手布置受预算约束的障碍，赛中搭建升级炮塔体系抵御镜像波次 | [CD-22](../20-gameplay/22-bastion.md) |

## 3. 一期锁定边界

以下 18 项视为锁定。完整来源追踪见 [CD-91 决策记录](../90-reference/91-decision-log.md)；列入 [CD-63](../60-plan/63-open-decisions.md) 的事项除外。

1. 玩法采用轻动作竞速和低动作塔防对战两条线；
2. 一期无账号级排位、MMR、段位和赛季，只做单局内名次或 MVP 结算；
3. 允许离线单人试玩，但离线成绩、奖励、战绩和解锁不回写在线服务；
4. 一期单区、固定容量，不做自动扩缩容、跨区和观战；
5. 主机平台暂不考虑；
6. 必须提供方便的 Edit 模式，并支持快速修改、预览、热发布和安全热生效；
7. TRAPRUSH 以道具、避障、障碍破坏和立体传送移动为核心；BASTION 以赛前互设障碍、赛中搭建炮塔体系为核心；
8. 开发方式为 AI 主导，人类负责目标、逐任务审查、纠偏和高风险决策；
9. 开发者以桌面原生客户端和 Headless 为主，测试者优先使用 Web 链接；共享功能持续通过 Web 兼容门禁；
10. Web 支持游玩和轻量编辑；桌面安装版提供完整规则图；Android/iOS 一期只游玩、评分和管理内容；
11. 两个玩法共用编辑器框架，通过玩法 Schema、验证器和专用工具面板扩展；
12. 一期线上环境位于腾讯云香港，仅有"本地 + 长期测试"两个长期环境；不存在正式 Production；
13. 一期所有实时客户端统一使用 WebSocket；控制面使用 JSON，实时对局使用版本化二进制 Schema；
14. `SimulationCore` 使用 64 位整数承载的定点数和确定性执行顺序，不以 Godot 浮点物理作为裁决依据；
15. 一场对局一个 Godot Headless 进程，由 MatchHost 管理并经独立 WebSocket 网关接入；
16. 控制面一期以 SQLite 起步且仅 Fastify 可直接访问，PostgreSQL 为后续迁移目标；
17. 公开 UGC 只允许平台资产与结构化内容，技术验证通过后在测试环境自动公开，不做人工前置审核；
18. 一期人类团队按一名核心负责人设计，路线图按里程碑而非固定周数推进。

## 7. 客户端技术边界

- 客户端固定使用 **Godot 4 Standard + GDScript**。工程中禁止引入 `.cs`、`.csproj` 和 Godot .NET 运行时，以保留 Web/微信小游戏导出路径；
- 渲染以 **Compatibility / WebGL 2** 为共同基线。PC 可以有 Forward+ 增强配置，但任何核心可读性和玩法反馈不得依赖 Forward+ 专属效果；
- 共享玩法、编辑器和仿真核心禁止依赖 GDExtension。原生平台适配层可在有 Web 空实现且不改变共享玩法语义时例外使用，例如后续 GodotSteam 适配。

## 8. 产品表现与设备基线

- 美术：统一风格化低多边形、清晰纯色分区和少量描边；两个玩法通过主题和色板区分；
- 资产来源（2026-08-30 拍板）：平台资产**允许由 AI 生成工具产出**（TRELLIS、混元 3D 等），产物只要过 §8.1 预算即可作为正式资产入库，不必再由人手重做；玩家上传模型、音频与贴图仍是第 5 节的不做项，AI 资产来源追溯、投诉与下架流程仍属 [CD-63 §4](../60-plan/63-open-decisions.md) 阻断清单；
- 语言：一期同时支持简体中文和英文，所有 UI 与系统文本从第一天使用本地化键。实现落点（2026-09-02）：`game/src/shared/ui_copy.gd` 用 `FileAccess.get_csv_line` 读 `res://content/locale/craft_arena.csv`（键前缀 `craft_arena.`，[§1](#1-项目名称与愿景)）。大厅 / Editor / Preview 的按钮、窗题、占位符与 CD-13 离线横幅走键。开发期状态行（`join=` / `pads=` / `FPS`）、节点名、课程 id、错误码、动画状态名不翻译。字体仍未入包（见 §8.2）。真导出包上的解析陷阱见 [desktop-export-check.md §5 第 6 条](../../docs/runbooks/desktop-export-check.md)。
- 目标年龄：青少年及成人，按 12+/13+ 设计，不主动面向低龄儿童；
- 商业化：一期不做广告、内购、付费货币、皮肤商业接口或创作者分成，也不预埋相关玩法钩子；
- 无障碍：原型期不设按键重映射、色盲、屏幕阅读或镜头震动开关等专项门禁；
- 最低设备参考：Windows 10/11 集显与 8 GB 内存、Android 10/4 GB 中端机、iPhone XR/SE2、桌面 WebGL 2；
- 帧率观察目标：PC/桌面 Web 60 FPS，移动最低 30 FPS，高档移动设备可选 60 FPS；
- 分发签名：Windows 测试包暂不购买代码签名；Android 使用测试/发布 keystore；iOS 遵循 TestFlight 签名要求。

### 8.1 单个 3D 资产预算（2026-08-30 拍板，当前生效值）

适用于**平台资产**（官方与 AI 生成，含 TRELLIS / 混元产物）。玩家仍不能上传自定义模型、音频与任意贴图（见第 5 节）。超限资产在入库前处理或拒绝（宪法第十七条）。

| 项 | 上限 |
|---|---|
| 三角面数 — 静态无绑定物件 | 3,000 |
| 三角面数 — 带动画绑定的角色 | 6,000 |
| 贴图边长（每张，全用途：baseColor / ORM / normal） | 512 |
| 单个资产文件体积 | 2 MB |

三条边界，避免被外推成它不是的东西：

1. 这是**单个资产**的准入线，不是场景总量、Draw call、材质数或骨骼上限——那几项属 C4 后续章，仍未拍板；
2. 面数按**三角形**计；生成器面板上的"面数"若是四边形面，须换算后再核对；
3. 512 是磁盘与显存双向的上限。编码格式（PNG / JPEG / KTX2）不在本表约束内，因为它只影响磁盘、不影响显存（观察依据见 [烘焙试验 §5.2](../../docs/plans/asset-bake-trial-2026-08.md)）。

来源与被覆盖关系见 [CD-91 D.1](../90-reference/91-decision-log.md)；观察数据见 [烘焙试验记录](../../docs/plans/asset-bake-trial-2026-08.md)（那份文档是一次本机试验，**不是**本表的所有者）。

### 8.2 表现规格（D4，2026-08-26 拍板；当前生效值）

[纠偏方案 D4](../../docs/plans/course-correction-2026-08.md) 的数值表在此落地。此前这些值只以"占位常量"形式活在代码里，本节起本文档是它们的所有者；实现侧的单一配置源是 [`game/src/shared/placeholder_spec.gd`](../../game/src/shared/placeholder_spec.gd)，两者冲突以本节为准。

| 项 | 当前生效值 | 已接线 |
|---|---|---|
| 1 格 = 多少表现米 | 1 m | 是 |
| 角色高度 / 半径（相对格） | 高 0.125 格 / 半径 0.125 格 | 是（权威胶囊） |
| 相机水平方位角 / 俯角 | 45° / 45° | 是（2026-08-31） |
| 相机距离 / FOV | **D4 未回答** ⇒ 维持接线前值（距离 √136 ≈ 11.66 m、FOV 75°） | 是（显式写在 spec，不再是隐式默认） |
| TRAPRUSH 色板 | 危险 = 洋红；固体 = 石色；可破坏箱 = 橙 | 是 |
| BASTION 色板 | **未回答**，不阻塞（M6/M7 冻结中） | — |
| UI 分辨率基准 | 1920×1080，按 `canvas_items` 等比缩放 | 是（2026-08-31，落在**主窗口** stretch） |
| UI 安全区 | **D4 未回答**。一期无移动端导出，无刘海与手势条要避让；触控 UI 立项（D7）时必须补答 | — |
| 描边 | 不做（D8），可读性靠色块 + 明度分区 | — |
| 中英文字体 | 思源黑体 / Noto Sans SC，子集化入包 | **否**，见下 |

三条边界：

1. **距离与 FOV 不是产品决策**。D4 只回答了角度，所以接线时一位数字都没改；它们显式写在 spec 里只是为了让下一次改镜头必须动那一处，不代表已被拍板；
2. **UI 基准 ≠ 窗口尺寸，且只落在主窗口**。开发机运行窗仍是 1600×900 最大化，两个代码创建的玩法窗口仍是 1280×720。玩法 HUD 画在那个 1280×720 的**嵌入子窗口**里，随主窗口的 1920×1080 基准整体放大，所以"HUD 按 1920×1080 设计"尚未成立（要让子窗口铺满或不用子窗口，属 C5 拆壳）。**嵌入子窗口不得自行设 `content_scale_*`**：`gui_embed_subwindows = true` 下它在渲染路径不生效、输入路径生效，会让鼠标命中与画面错开 `1/factor` 倍（2026-08-31 在 4K 屏上实测：点 Solo play 命中 Poll）；
3. **字体尚未入包**。它是新增第三方资产与许可证（宪法第十八条人类门禁），且子集范围会直接影响 Web 包体：项目内中文串已收到本地化键表，但公开未过滤用户名（[CD-62](../60-plan/62-risk-register.md)）意味着玩家昵称是任意汉字，只按项目文本子集会让昵称变豆腐块。范围须由人类拍板。**本地化键已接线**（C4 第 12 章，`UiCopy` + `content/locale/craft_arena.csv`），不再跟字体绑成同一刀。

来源见 [CD-91](../90-reference/91-decision-log.md)。

## 9. 公开 Web 与传输安全（D2 / D11）

- Web 是一期持续测试入口（§6）。C1 已含 Web 导出预设，见 [CD-51 §5](../50-engineering/51-dev-environment.md)。
- 测试开发阶段允许明文 `http`（控制面）与 `ws`（网关）打到自备远端测试机，见 [CD-43 §2](../40-technical/43-networking-and-replay.md)。
- **域名 + 受信证书在公开运营前补齐**，不是 C1 必须项。浏览器 HTTPS 页不能混用 `ws://`、也不接受自签，故公开 Web 联机仍须域名。
- 不得对外表述为已具备 TLS。一期产品形态仍是宪法第二十二条的 TLS WebSocket 网关。
