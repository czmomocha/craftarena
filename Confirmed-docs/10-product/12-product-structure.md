## 1. 入口结构

首版是同一品牌、账号和大厅下的模块化产品。两个玩法代码随基础客户端发布，首次进入频道时再按需下载该玩法的可信资源、官方内容和 UGC 数据。

```text
主大厅
├─ 机关狂奔
│  ├─ 快速游戏
│  ├─ 房间码
│  ├─ 单人试玩
│  └─ 关卡编辑（桌面完整 / 桌面 Web 轻量）
├─ 双塔要塞
│  ├─ 快速游戏
│  ├─ 房间码
│  ├─ 单人对 AI
│  └─ 蓝图编辑（桌面完整 / 桌面 Web 轻量）
├─ 我的内容
│  ├─ 草稿
│  ├─ 已发布版本
│  └─ 内容管理
├─ 公共内容
│  ├─ 最新
│  ├─ 评分
│  ├─ 游玩次数
│  └─ 已验证
└─ 设置
```

实现落点见 [CD-44 §3](../40-technical/44-deployment.md#3-进程隔离与租约)：控制面快速游戏、房间码与容量满 FIFO。机关狂奔入口已落到 `MatchLobbyShell`（代码创建 Window：快速游戏 / 建房 / 按码加入 / 官方赛道 id / 本场人数 / 队列位次与预计等待 / 取消 / 单人试玩；持票后跟从最新快照，并把相邻两份快照采样后的玩家位姿、本场编译拓扑的垫 / 门 / 终点，以及可破坏箱（拓扑位姿 + 快照耐久）映射为 1 米占位盒，并把 classified portal 源点→终点画成 gizmo 条，并把检查点垫 `order` 打标、唯一 `order` 按升序连线，并把最新快照的直播名次标到玩家盒上方；本席 Move/Jump 在最新权威上叠加本地 overlay，远端仍插值；大厅 WASD 把 8 向离散水平 `yaw_bam` 写入已有 Move（W=0 为 -Z，省略哨兵仍是 -1），玩家盒带 local -Z 面向标记；SnapshotCamera 跟随本席表现位姿，偏移与 Preview 相同，远端不拉镜头；本席玩家盒用 `OWN_ALBEDO`（青），远端仍 `REMOTE_ALBEDO`；名次标本席前缀 `*`；本席 `accepted_count` 把检查点垫分成已验收 / 当前目标 / 未到；本席 `finish_tick` 把终点分成未到 / 当前目标 / 已冲线；HUD 写 `pads=n/m` / `floor=n` / `finish=n` / `crates=n/m`，全员冲线后加 `result=`；线上再 GET 控制面结算记录，200 后加 `settled=`；R 把已有 ResetToCheckpointIntent 接到可见复位）。**Cancel** 停 Solo、取消等待队列，并在 connecting / in_match 时本地离开（立即断开网关、不补票、清玩家盒与名次标、镜头回原点）；不锁离开对局 HTTP。快速游戏与建房发送官方赛道 id 与本场 `seats`；按码加入跟从该房已锁课程与人数并重编译同一份。入场就绪 JSON 带本票 `seat`。单人试玩走本地内嵌 `TraprushMatchSession`，复用赛道选择器（仍为 1 人），HUD 持续显示「离线试玩，成绩不上传」，不发 HTTP/WS，Web 拒绝。全员冲线后的单局名次写库由对局进程心跳 + MatchHost 活场 flush（停止前再 POST 一次，409 视为已写入）+ 控制面完成；大厅只读 GET 面板，不 POST。对局中**意外**断线后大厅用已消费票补发同席位新票再入场，并跟从最新快照。双塔要塞入口、内容页与设置仍待。名次规则见 [CD-13 §4](13-account-and-session.md#4-单局排名) 与 [CD-21 §6.1](../20-gameplay/21-traprush.md#61-排序优先级)。

## 2. 内容发现规则

- 一期不做个性化推荐和创作者商业化；
- 公共内容使用四个固定标签页：最新、评分、游玩次数、已验证；
- 机器人或真人尚未完成过的内容仍可公开，但标记"未验证可完成"，且不进入默认"已验证"筛选；
- 内容名称由系统或预设词库组合，说明只使用结构化标签，不提供自由文本。

## 3. 刷屏治理（已接受风险）

平台不自动对"最新"列表做内容哈希去重、作者折叠或占比限制；刷屏由管理员手动清理。

此策略属于已接受风险，不代表具备公共内容治理能力，详见 [CD-62 风险登记册](../60-plan/62-risk-register.md)。
