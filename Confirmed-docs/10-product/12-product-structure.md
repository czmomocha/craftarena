## 1. 入口结构

首版是同一品牌、账号和大厅下的模块化产品。两个玩法代码随基础客户端发布，首次进入频道时再按需下载该玩法的可信资源、官方内容和 UGC 数据。

```text
主大厅
├─ 机关狂奔
│  ├─ 快速游戏
│  ├─ 房间码
│  ├─ 单人试玩
│  └─ 关卡编辑（桌面完整 / 桌面 Web 轻量）
├─ 双塔要塞
│  ├─ 快速游戏
│  ├─ 房间码
│  ├─ 单人对 AI
│  └─ 蓝图编辑（桌面完整 / 桌面 Web 轻量）
├─ 我的内容
│  ├─ 草稿
│  ├─ 已发布版本
│  └─ 内容管理
├─ 公共内容
│  ├─ 最新
│  ├─ 评分
│  ├─ 游玩次数
│  └─ 已验证
└─ 设置
```

实现落点见 [CD-44 §3](../40-technical/44-deployment.md#3-进程隔离与租约)：控制面快速游戏、房间码与容量满 FIFO。大厅 UI 仍待。

## 2. 内容发现规则

- 一期不做个性化推荐和创作者商业化；
- 公共内容使用四个固定标签页：最新、评分、游玩次数、已验证；
- 机器人或真人尚未完成过的内容仍可公开，但标记"未验证可完成"，且不进入默认"已验证"筛选；
- 内容名称由系统或预设词库组合，说明只使用结构化标签，不提供自由文本。

## 3. 刷屏治理（已接受风险）

平台不自动对"最新"列表做内容哈希去重、作者折叠或占比限制；刷屏由管理员手动清理。

此策略属于已接受风险，不代表具备公共内容治理能力，详见 [CD-62 风险登记册](../60-plan/62-risk-register.md)。
